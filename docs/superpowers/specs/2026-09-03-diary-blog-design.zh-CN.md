# Diary Blog 博客系统设计说明

日期：2026-09-03

状态：已确认

文档用途：中文设计归档

## 1. 项目概述

Diary Blog 是一个面向个人技术写作的轻量博客系统，核心目标是：写作方便、阅读快速、部署简单、数据可靠。

系统采用以下技术方案：

- 后端：Go + chi。
- 公开页面：Go `html/template` 服务端渲染。
- 管理后台：Vue 3 + TypeScript + Vite 单页应用。
- 数据库：SQLite。
- 全文搜索：SQLite FTS5 trigram 索引。
- 文章格式：Markdown。
- 部署：Docker Compose。
- HTTPS 与反向代理：Caddy。
- 持久化内容：SQLite 数据库、媒体文件和备份文件。

整个系统保持模块化单体结构，不引入 Redis、消息队列、独立搜索引擎或其他分布式组件。

## 2. 建设目标

- 管理员可以通过浏览器后台编写和发布 Markdown 文章。
- 公开页面直接输出完整 HTML，保证首屏速度和搜索引擎收录效果。
- 支持分类、标签、归档和全文搜索，方便长期积累技术内容。
- 支持草稿、预览、发布、归档和历史版本恢复。
- 发布失败时继续保留并展示上一个成功版本。
- 使用单个 Go 应用进程完成页面、API、搜索和内容处理。
- 通过 Docker Compose 完成可重复部署。
- 支持数据库与媒体文件的一致性备份和恢复。
- 页面在桌面端和移动端均保持清晰、易读且无布局重叠。

## 3. 首版不包含的功能

- 读者注册。
- 多作者协作。
- 文章评论。
- 邮件订阅和 Newsletter。
- 邮件找回密码。
- 实时协同编辑。
- 插件市场和主题市场。
- 多节点部署和水平扩容。
- 完全依赖 JavaScript 的公开网站。

这些功能不属于首版范围，只有出现明确需求后才考虑增加。

## 4. 总体架构

### 4.1 公开博客

公开博客使用 Go `html/template` 进行服务端渲染。

浏览器访问首页、文章页、分类、标签、归档或搜索结果时，Go 应用直接返回完整 HTML。即使浏览器禁用 JavaScript，用户仍然可以浏览和阅读文章。

公开页面中的 JavaScript 仅用于渐进增强，例如：

- 移动端导航。
- 搜索建议。
- 复制文章链接。
- 阅读偏好。

文章展示、分类导航和搜索结果不能依赖 JavaScript 才能使用。

### 4.2 管理后台

管理后台使用 Vue 3 + TypeScript + Vite 开发，通过 `/admin` 提供访问。

后台编译后的静态资源嵌入 Go 二进制文件，不需要额外运行 Node.js 服务。

后台通过 `/api` 下的 JSON API 完成：

- 管理员登录和退出。
- 仪表盘统计。
- 文章新建、编辑、查询和归档。
- Markdown 编辑和服务端预览。
- 草稿自动保存。
- 发布和重新发布。
- 历史版本查看与恢复。
- 分类和标签管理。
- 图片上传和媒体管理。
- 站点名称、简介、导航和 SEO 设置。

### 4.3 Go 模块化单体

Go 应用负责：

- 公开页面路由和模板渲染。
- 管理后台 JSON API。
- 身份认证、会话和权限校验。
- Markdown 解析、安全过滤、代码高亮和目录生成。
- 文章草稿、版本和发布流程。
- SQLite 数据访问和数据库迁移。
- 全文索引更新和搜索。
- RSS 与站点地图生成。
- 公开页面进程内缓存。
- 日志、健康检查、备份与恢复命令。

HTTP 处理器只负责协议转换和响应，业务规则放在应用服务中，SQLite 实现放在仓储层中。

建议目录结构：

```text
diary_blog/
  cmd/blog/                 程序和命令行入口
  internal/auth/            密码、会话、CSRF 和权限
  internal/content/         Markdown 与文章业务规则
  internal/http/            公开页面、管理 API 和中间件
  internal/platform/        配置、日志、时钟和标识符
  internal/repository/      仓储接口与 SQLite 实现
  internal/search/          全文索引和搜索
  internal/site/            RSS、站点地图和公开视图模型
  migrations/               SQLite 数据库迁移
  web/templates/            Go 页面模板
  web/static/               公开样式、图标和静态资源
  admin/                    Vue 管理后台源码
  deploy/                   Caddy 和部署配置
  tests/e2e/                Playwright 端到端测试
  Dockerfile
  compose.yaml
```

## 5. 页面与交互设计

### 5.1 视觉方向

系统采用已确认的“知识库式”视觉方案。

主色使用森林绿，背景以白色和浅灰绿色为主，金色用于关键操作，蓝色和红色只用于状态、链接和警告。

设计原则：

- 文字和内容优先。
- 页面信息密度适中，便于快速浏览。
- 不使用大量装饰卡片。
- 不使用过度圆角、渐变光斑或营销式大标题。
- 公开页面强调阅读体验。
- 管理后台强调效率和稳定布局。
- 图标按钮使用统一图标库，并提供无障碍标签或提示。

### 5.2 公开页面

首版包含：

- 首页和文章列表。
- 文章详情页。
- 分类详情页。
- 标签详情页。
- 时间归档页。
- 全文搜索结果页。
- 关于页面。
- RSS。
- XML Sitemap。

桌面端首页使用左侧分类导航和右侧文章列表。移动端收起侧栏，切换为单列布局。

文章详情页包含：

- 标题。
- 分类和标签。
- 发布时间与更新时间。
- 预计阅读时间。
- Markdown 正文。
- 代码语法高亮。
- 标题锚点。
- 桌面端粘性文章目录。
- 移动端可折叠目录。

### 5.3 管理后台

后台编辑器采用工作台布局：

- 左侧：后台导航。
- 中间：标题和 Markdown 编辑区域。
- 右侧：分类、标签、封面、状态和发布时间等设置。
- 顶部：预览、保存草稿和发布操作。

窄屏状态下，左右面板折叠，但编辑内容和未保存状态必须保留。

## 6. 数据模型

### 6.1 文章 `posts`

主要字段：

- `id`
- `slug`，唯一
- `title`
- `summary`
- `content_md`
- `content_html`
- `content_plain`
- `status`：`draft`、`published` 或 `archived`
- `category_id`
- `cover_media_id`
- `published_at`
- `created_at`
- `updated_at`

Markdown 是文章的源数据。HTML 和纯文本属于可重新生成的数据。

文章第一次创建时生成 slug。文章发布后修改标题不会自动修改 slug，避免已有外部链接失效。

### 6.2 历史版本 `post_revisions`

文章正文或重要元数据发生变化时保存历史版本。

每篇文章默认保留最近 30 个版本，管理员可以查看并恢复任意保留版本。

### 6.3 分类和标签

- `categories`：分类名称、slug 和时间字段。
- `tags`：标签名称、slug 和时间字段。
- `post_tags`：文章与标签的多对多关系。

一篇文章最多属于一个分类，可以包含多个标签。

### 6.4 媒体 `media`

媒体表只保存：

- 文件路径。
- MIME 类型。
- 图片宽高。
- 文件大小。
- 替代文本。
- 创建时间。

图片文件保存在持久化媒体目录，不存入 SQLite BLOB 字段。

### 6.5 管理员和会话

- `admins`：用户名、密码哈希和时间字段。
- `sessions`：会话令牌哈希、管理员 ID、过期时间和最后访问时间。

系统预期只有一个管理员，但数据层不使用固定管理员 ID。

### 6.6 全文搜索

`posts_fts` 使用 SQLite FTS5 trigram tokenizer，索引以下内容：

- 标题。
- 摘要。
- 文章纯文本。

只有已发布文章进入公开搜索索引。草稿和归档文章不能出现在搜索结果中。

trigram 方案用于支持中文、英文技术标识符以及中英文混合内容。测试必须覆盖中文词语、拉丁字符和混合语言搜索。

全文索引属于派生数据，可以根据 `posts` 表完整重建。

### 6.7 设置和迁移

- `site_settings`：站点名称、简介、作者、导航、社交链接和 SEO 默认值。
- `schema_migrations`：已执行的数据库迁移版本。

数据库迁移文件嵌入 Go 二进制。应用启动时自动执行迁移，迁移成功后 readiness 才能通过。

## 7. 文章发布流程

1. 管理后台自动保存 Markdown 草稿和文章元数据。
2. API 校验标题、slug、分类、标签、正文大小和并发版本。
3. 预览功能调用后端 Markdown 渲染器。
4. 正文发生实际变化时保存历史版本。
5. 发布时渲染并过滤 HTML，生成纯文本、标题目录和阅读时间。
6. 在同一个 SQLite 事务中更新文章状态和全文索引。
7. 事务提交成功后清理文章、首页、分类、RSS 和 Sitemap 缓存。

如果校验、渲染、数据库写入或全文索引更新失败，整个发布事务回滚，公开页面继续展示上一次成功发布的版本。

草稿自动保存携带最后一次已知更新时间或版本号。出现编辑冲突时，后台必须保留本地正文，并让管理员选择重新加载或覆盖。

## 8. HTTP 路由

### 8.1 公开路由

```text
GET /                              首页与文章列表
GET /posts/{slug}                  文章详情
GET /categories/{slug}             分类详情
GET /tags/{slug}                   标签详情
GET /archive                       时间归档
GET /search?q=                     搜索结果
GET /about                         关于页面
GET /rss.xml                       RSS
GET /sitemap.xml                   XML Sitemap
GET /media/{path}                  媒体文件
GET /healthz                       存活检查
GET /readyz                        就绪检查
```

### 8.2 管理 API

```text
POST   /api/auth/login
GET    /api/auth/session
DELETE /api/auth/session

/api/admin/posts
/api/admin/posts/{id}/preview
/api/admin/posts/{id}/publish
/api/admin/posts/{id}/revisions
/api/admin/categories
/api/admin/tags
/api/admin/media
/api/admin/settings
```

API 错误返回稳定错误码、请求 ID 和字段级校验信息，不向浏览器暴露 SQL 或堆栈信息。

## 9. 安全设计

- 不提供公开注册接口。
- 使用命令行初始化或重置管理员密码。
- 密码使用 Argon2id 哈希。
- Cookie 设置 `Secure`、`HttpOnly` 和 `SameSite`。
- 会话默认有效期为 12 小时。
- SQLite 只存储会话令牌哈希，不保存原始令牌。
- 所有后台写操作必须进行 CSRF 和同源校验。
- 登录接口按用户名和客户端 IP 限流。
- Markdown 默认禁止原始 HTML。
- 渲染结果过滤危险标签、属性和 URL 协议。
- 图片上传验证真实内容和 MIME 类型。
- 单个上传文件最大 10 MB。
- 上传文件使用随机生成的存储名称。
- 日志不得记录密码、Cookie、会话令牌或完整文章正文。

## 10. 性能与 SQLite 设置

- 开启 WAL 模式。
- 开启外键约束。
- 设置有界的 busy timeout。
- 数据库写事务保持短小。
- 数据库事务中不执行图片文件写入等慢速 I/O。
- 默认分页数量为 20，最大为 100。
- 公开页面和 RSS 使用进程内缓存。
- 文章发布和站点设置修改后精确清理相关缓存。
- 静态资源使用带指纹文件名和长期缓存响应头。
- 首版不使用 Redis。

## 11. Docker 部署

Docker Compose 包含两个服务：

- `caddy`：对外暴露 80 和 443 端口，负责 HTTPS、压缩、安全响应头和反向代理。
- `blog`：运行 Go 应用，只在 Compose 内部网络监听。

生产镜像采用多阶段构建：

1. Node.js 构建 Vue 管理后台。
2. Go 编译应用，并嵌入模板、迁移和前端静态资源。
3. 最终镜像只保留运行所需文件和非 root 用户。

持久化目录：

```text
/data/blog.db
/data/media/
/data/backups/
```

配置通过环境变量或挂载配置文件提供。密钥不能写入镜像或提交到 Git。

`/healthz` 只检查进程是否存活。`/readyz` 检查数据库、迁移状态和数据目录是否可用。

## 12. 备份与恢复

应用提供以下命令：

- `blog backup`：通过 SQLite 在线备份生成一致性数据库副本，并与媒体文件、清单一起归档。
- `blog restore`：验证备份清单，并恢复到空目录或经过明确确认的目录。
- `blog migrate`：执行待处理数据库迁移。
- `blog admin reset-password`：初始化或重置管理员密码。

备份任务由 Docker 宿主机定时执行。

正式发布前必须完成一次恢复演练：把备份恢复到空目录，启动系统，并确认文章与图片可以正常访问。

## 13. 错误处理与日志

- 每个 HTTP 请求生成 request ID。
- 日志使用结构化格式。
- 日志记录路由、方法、状态码、耗时和错误分类。
- 公开错误页不显示内部实现细节。
- API 不返回 SQL、文件绝对路径或堆栈信息。
- 网络失败时，后台保留未保存的 Markdown 内容。
- 发布失败时指出失败阶段，但不影响现有公开版本。
- 应用支持优雅关闭，并在限定时间内处理完成正在执行的请求。

## 15. 首版验收标准

- 管理员可以登录、退出和重置密码。
- 管理员可以新建、预览、保存、发布、编辑、归档和恢复文章。
- 公开用户可以按首页、分类、标签、归档和搜索浏览文章。
- 公开页面直接返回完整 HTML。
- 禁用 JavaScript 后仍然可以阅读和导航。
- 草稿与归档内容不会出现在公开列表、RSS、Sitemap 或搜索中。
- Markdown 输出经过安全过滤。
- 代码块在桌面端和移动端均可正常阅读。
- Docker Compose 启动后数据和图片可以持久化。
- 备份可以完整恢复 SQLite 和媒体文件。
- 自动化测试覆盖从写作到公开发布的关键流程。
- Playwright 截图中不存在文字、按钮和面板异常重叠。

## 16. 实施约束

- 采用测试驱动开发实现核心业务和数据库迁移。
- 路由、Markdown、HTML 过滤、编辑器和端到端测试优先使用成熟库。
- Markdown 始终是文章源数据。
- HTML 和全文搜索索引必须可以重建。
- 生产环境只运行 Caddy 和一个 Blog 应用进程。
- 未出现明确首版需求时，不增加新的基础设施组件。
- 保持模块边界清晰，不为尚不存在的扩展需求提前设计复杂插件系统。
